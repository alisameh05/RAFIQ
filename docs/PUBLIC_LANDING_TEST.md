# P01 public landing evidence

[Issue #25](https://github.com/alisameh05/RAFIQ/issues/25) covers ACC-01/ACC-06, M01/M10, FR-01/AC-01, NFR-04 and J1. The public surface uses the account-entry and signup settings from the [email account-entry runbook](ACCOUNT_ENTRY_TEST.md).

## Reproduce the browser checks

- Run `RAFIQ_LANDING_LOCAL=1 npm run test:e2e -- landing.spec.ts` from `web/` on the CI runtime. Playwright starts a disposable Next.js origin in the held state. The [fixture workflow](../.github/workflows/local-fixture.yml) publishes the synthetic screenshots as `synthetic-landing-evidence`.
- To check both destinations on the isolated Clerk development configuration, set `RAFIQ_LANDING_ENABLED_ORIGIN` to the enabled web origin and run `npm run test:e2e -- landing.spec.ts`. Use matching Clerk development settings from the account-entry runbook. `RAFIQ_LANDING_PENDING_ORIGIN` accepts a separate held origin. For returning sign-in qualification, use the approved development identity on the invite-only instance.
- Record the candidate SHA and browser run link in the PR. Use the build's Next.js and Clerk versions from the [web lockfile](../web/package-lock.json). The fixture is synthetic parked-session data with no private records. The review owner for this record is Product UI. Product UI, the asset owner, and Release own the remaining approvals.
