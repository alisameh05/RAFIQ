Use one phase section as input to [`to-spec`](../.agents/skills/to-spec/SKILL.md). Keep the goal and actors, derive extensive user stories from the listed slices and their failure cases, carry closed decisions and proposed contracts into implementation decisions, and carry the phase evidence into testing decisions. Each row below is a **candidate vertical slice**, identified by a local reference such as `ACC-01`. Turn a row into smaller tickets when a collaborator cannot build and verify the whole behavior in one working context. Carry forward the dependency edges that genuinely block a slice. Parallel UI, fixtures and adapter prep may start before an integration blocker is complete. Keep the completion edge on the integrated behavior. Create native blocking links and a phase-spec parent where supported, and use the tracker’s agreed readiness label. Keep owner approvals, provisioning, evidence collection and operator tasks explicitly human-owned. Give each ticket behavior, acceptance checks, screen/frame links, source IDs, dependencies and one place to find its evidence.

For a gated provider, split the integrated behavior and its live qualification when a credential or external approval could delay the second ticket. The implementation ticket delivers and verifies the supported and unavailable paths. The qualification ticket records a pass or identifies the blocking prerequisite. Carry both outcomes into REL-04. A pending disposition preserves the launch constraint.
